= Lexical Structure Specification
:navtitle: Lexical Structure

This chapter specifies the lexical grammar and token structure of the Bourbon programming language, corresponding to the compiler's lexical scanner implementation.

---

== Source Representation

Bourbon source text consists of a sequence of Unicode characters encoded in UTF-8. The lexical scanner transforms this stream of characters into discrete tokens, discarding whitespace and comments while emitting structured diagnostics for invalid sequences.

An explicit end-of-file token (`EOF`) is synthesized at the end of the input stream. In interactive or incremental compilation contexts (such as REPL multi-line evaluation), the scanner can resume tokenization seamlessly as new input is appended.

---

== Whitespace and Comments

=== Whitespace

Whitespace characters separate adjacent tokens and are otherwise discarded by the scanner:

* Space (`' '`, ASCII 32)
* Horizontal tabulation (`'\t'`, ASCII 9)
* Carriage return (`'\r'`, ASCII 13)
* Line feed (`'\n'`, ASCII 10)

=== Comments

Bourbon supports two styles of comments:

* **Line Comments**: Begin with `//` and extend to the end of the current line or input stream.
* **Block Comments**: Begin with `+/*+` and terminate with `+*/+`.

Block comments may be **nested** arbitrarily deep:

[source,bourbon]
----
/* Outer comment
    /* Nested inner comment */
   Still inside outer comment */
----

If the input ends before all nested block comments are balanced and closed, the scanner issues an `unbalancedMultilineComment` diagnostic pinpointing the opening delimiter.

== Numeric Literals

Bourbon supports three integer bases (binary, hexadecimal, and decimal), floating-point decimals, standard metric magnitude suffixes, and scientific exponent notation. Numeric values are represented with arbitrary precision (`BigDecimal` and `BigInteger`) to ensure zero precision loss during compilation.

=== Digit Separators (`_`)

Underscores (`_`) may be placed within numbers to visually group digits. The placement of underscores is strictly checked according to the following uniform rules:

* **No Leading Underscores**: An underscore cannot appear at the start of a decimal literal, nor immediately following the base prefix (`$` or `#`). Examples of invalid literals: `$_01`, `#_ff`.
* **No Trailing Underscores**: An underscore cannot be the final character of any numeric literal. Examples of invalid literals: `123_`, `10_`.
* **No Consecutive Underscores**: Double or multiple consecutive underscores are strictly disallowed. Examples of invalid literals: `1__000`, `$10__01`, `#ff__ff`.
* **No Underscore Adjacent to Decimal Point**: An underscore cannot appear immediately before (`1_.2`) or immediately after (`1._2`) a decimal point.

=== Binary Integer Literals

Binary literals represent integers in base 2:

* **Prefix**: Dollar sign (`$`).
* **Valid Digits**: `0`, `1`.
* **Requirements**: At least one binary digit must follow the `$` prefix.
* **Examples**: `$0`, `$1`, `$01`, `$10010`, `$1010_0101`, `$1111_0000_1010_0101`.

=== Hexadecimal Integer Literals

Hexadecimal literals represent integers in base 16:

* **Prefix**: Hash sign (`#`).
* **Valid Digits**: `0` through `9`, `a` through `f`, and `A` through `F` (case-insensitive).
* **Requirements**: At least one hexadecimal digit must follow the `#` prefix.
* **Examples**: `#0`, `#01`, `#2345`, `#abcdef`, `#ABCDEF`, `#ff_ff_ff_ff`, `#1234_5678_9abc_def0`.

=== Decimal Integers

Decimal integer literals represent numbers in base 10:

* **Valid Digits**: `0` through `9`.
* **Requirements**: Must begin with a decimal digit. Leading decimal points (such as `.5`) are not permitted; `0.5` must be used instead.
* **Examples**: `0`, `1234`, `1_000`, `1_234_567_890`.

=== Floating-Point Literals

Floating-point literals represent fractional decimal numbers:

* **Format**: One or more decimal digits, followed by a decimal point (`.`), followed by one or more decimal digits.
* **Requirements**: At least one digit must precede and at least one digit must follow the decimal point. A literal may contain at most one decimal point; sequences such as `1.2.3` produce a `Multiple decimal points in numeric literal` diagnostic.
* **Examples**: `0.0`, `1.5`, `123.456`, `1_000.000_1`.

=== Metric Magnitude Suffixes

Decimal integers and fractional numbers can be suffixed with an SI metric magnitude indicator to scale the value:

[cols="1,2,2,2", options="header"]
|===
| Suffix | Magnitude Name | Multiplier | Example
| `k` | Kilo | 10^3^ (1,000) | `1k`
| `M` | Mega | 10^6^ (1,000,000) | `2M`
| `G` | Giga | 10^9^ (1,000,000,000) | `3G`
| `T` | Tera | 10^12^ (1,000,000,000,000) | `4T`
| `P` | Peta | 10^15^ (1,000,000,000,000,000) | `5P`
| `m` | Milli | 10^-3^ (0.001) | `1m`
| `u` | Micro | 10^-6^ (0.000001) | `2u`, `10.25u`
| `n` | Nano | 10^-9^ (0.000000001) | `3n`
| `p` | Pico | 10^-12^ (0.000000000001) | `4p`
| `f` | Femto | 10^-15^ (0.000000000000001) | `5f`
|===

* Magnitude suffixes are case-sensitive (e.g. `m` represents milli, while `M` represents Mega).
* Fractional values may also use magnitude suffixes (e.g. `1.5k`, `10.25u`).
* Only a single suffix is permitted; compound suffixes such as `1km` are rejected.

=== Scientific Notation (Exponents)

Floating-point numbers may be written using scientific notation:

* **Format**: An exponent character (`e` or `E`), followed by a **mandatory sign** (`+` or `-`), followed by one or more decimal digits.
* **Mandatory Exponent Sign**: Unlike some languages where the sign is optional for positive exponents, Bourbon requires an explicit sign (`+` or `-`). Unsigned forms like `1e5` produce a `Missing sign in decimal exponent` diagnostic.
* **Multiple Exponents**: Only one exponent marker is allowed per literal. Formats like `1e+2e+3` produce a `Multiple exponents in decimal literal` diagnostic.
* **Examples**: `1e+5`, `1e-5`, `1.23E+10`, `123.45e-3`.

== Lexical Disambiguation Rules

The scanner applies targeted lookahead rules to avoid ambiguities in the grammar:

1. **Decimal Point vs. Range Operator**:
   A dot following decimal digits is only treated as part of a floating-point number if the character following the dot is also a decimal digit (`peek('.') && isDigit(peekNext())`).
   * `1..10` is scanned as `NUMBER(1)`, `DOT_DOT(..)`, `NUMBER(10)`.
   * `1.toString()` is scanned as `NUMBER(1)`, `DOT(.)`, `IDENTIFIER(toString)`.
   * `1.0` is scanned as `NUMBER(1.0)`.

2. **Exponent Notation vs. Binary Operators**:
   Because scientific notation requires an explicit sign (`e+` or `e-`), the sequence `1e+5` is greedily matched as a single float token rather than an identifier `1e` followed by the addition operator `+`.

3. **Greedy Error Recovery**:
   When scanning invalid numbers (e.g. `12a3`, `1.2.3`, `1e+2e+3`, `1km`), the scanner greedily consumes the entire ill-formed sequence. This prevents malformed numeric literals from cascading into spurious operator or identifier tokens downstream in the parser.
